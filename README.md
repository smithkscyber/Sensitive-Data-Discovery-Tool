# General Summary

Python based detection tool combining regex pattern matching and Microsoft Presidio's NLP engine to identify SSNs, credit card numbers, emails, phone numbers, and addresses across document sets, modeling data governance workflows used in e-discovery and compliance.

# The Problem it Solves

Companies accumlate thousands of documents overtime, many of them containing Personally Identifiable Information (PII). In a scenario where a company has to check thousands of these files for PII, the time would take months. With detection tools like  like this, that time is decreased dramatically.

# How It Works

Every file passes through a five stage process

Stage 1 : Open the file and extract the text
    A docx, PDF, spreadsheet, or email all store text completely different. Each file type has its text reader because each file type formats text differently.

Stage 2: Photograph the page and extract text
    In the event the file is a picture of a document the scanner recognizes that there is no actual text within the document and takes a snapshot of the image and reads the characters off the image

Stage 3: Uses a dual search method
    The search method combines context and data together to gather the what the data means while keeping the context it was given - see "Search Method" for more in depth explanation

Step 4: Scoring system that measures potential damage
    Each file gets a total severity of all of the data that was discovered - see "Scoring System" for more in depth explanation

Step 5: Ranked Report
    Files are ranked by severity to determine which ones should be treated as priority


# Search Method

There are different methods this project interprets PII data in a file. There is the actual data that is resembled in numbers, names, and information; then there is the context in which it is given

- Method 1: Shape Matching
    Some information is easily recognizable such as an SSN, which is always structured the same way in the same shape (000-00-0000). This is shaped information is easily recognizable by the program

- Method 2: Data Context
    In some instances data may look the same. A name is just words without given the right context and this method checks for context to distinguish the data as a name, street, or any other PII. For example, a credit card number could potentially match an order number and without the context it could be weighted as the wrong one

Neither is efficient when used by themselves. The Shape matching is not able to detect dynamic data such as names,streets, and things of that nature without the context of the information. Data context was not able to detect all cases where shape matching at 100% precision.

# How accuracy is measured

Before any detection code was written, Faker python package generated a set of fake documents ranging from memos, contact lists, and letters that containd realistic yet not real data that can be used for testing. To fully test the accuracy and precision of this program, decoy information that looks like PII data but is not was also incorporated in some of the documents

Precision = when it is flagged, is it a genuine alert. A low precision weight means that majority of the data that is flagged is junk
- Equation: precision = TP/(TP + FP) 
- True Positive(TP) = Flagged something that was actually a risk
- False Positive(FP) = Flagged something that was not a risk

Recall = Of all of the data that should have been flagged, how much of it was actually flagged
- TP/(TP +FN)
- True Positive(TP) = Flagged something that was actually a risk
- False Negative(FN) = Missed something that should have been flagged

F1 = Combines precision and recall -> (2(Precision * Recall))/(Precision + Recall)

# Document Severity Rating

Every document is given a risk score, that score is determined by what PII data is within the document. Not all PII data is equal when it comes to how damaging the data leak could be. Each type of SSN is ranked on a scale of 1-10.

- SSN: 10
- Credit Card: 9
- Home Address: 5
- Email Address: 3
- Network Address: 3
- Phone Number: 2
- Name: 2

However, sheer volume can impact the severity of a document. For example, a document containing 1 SSN and 10 names will not have the same severity rating as a document with just an SSN. To avoid this a document will always be ranked off its single highest severity score. A document containing an SSN will always have a score of 10 so it is prioritized.
